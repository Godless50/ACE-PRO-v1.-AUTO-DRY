# ESP32 внутри корпуса ACE Pro

Читает датчик влажности Xiaomi LYWSD03MMC по BLE и передаёт показания в
Moonraker командой `ACE_SET_RH`. Заменяет серверный контейнер `feeder/`,
убирая из цепочки сервер, адаптер BlueZ и прохождение BLE через стенку
корпуса.

Решения о нагреве принимает штатный механизм автосушки multiACE. Эта
прошивка — курьер без собственной логики.

## Главное правило безопасности

**При неудачном чтении датчика не отправляется ничего.**

Старое значение продлило бы срок годности показания и оставило нагреватель
включённым вслепую: команда запуска сушки уходит в ACE с длительностью 600
минут, само устройство не остановится. Молчание же через `RH_TTL_SECONDS`
заставит модуль `ace_ext_rh.py` на принтере погасить нагрев.

Севшая батарейка датчика, зависший Wi-Fi или сгоревшая плата приводят к
остановке сушки, а не к бесконечному нагреву.

## Сборка

```bash
cp include/config.example.h include/config.h
$EDITOR include/config.h          # сеть, адрес датчика, адрес принтера
pio test -e native                # тесты чистой логики, без железа
pio run -e esp32 -t upload        # прошивка по USB
pio device monitor                # журнал
```

Прошивка по воздуху, когда плата уже в корпусе:

```bash
pio run -e esp32_ota -t upload --upload-port 192.168.4.XX
```

Запасной путь обновления — веб-страница `http://<адрес>/update`
(ElegantOTA). Логин и пароль берутся из `OTA_HOSTNAME` и `OTA_PASSWORD`.

Состояние платы: `http://<адрес>/status` отдаёт JSON с последней командой,
длительностью молчания, счётчиками доставленных и потерянных показаний.

## Устройство кода

Логика, которую можно проверить без железа, вынесена в `lib/rhcore` и не
включает ни одного заголовка Arduino:

| Файл | Что делает |
|---|---|
| `reading.h` | структура показания, всё в целых единицах |
| `payload.*` | разбор пятибайтового уведомления датчика |
| `gcode.*` | сборка строки `ACE_SET_RH` |
| `cycle.*` | счётчики неудач, переинициализация BLE, перезагрузка |

Аппаратный слой в `src/`: `ble_sensor.*` (NimBLE), `net.*` (Wi-Fi, HTTP,
MQTT, обновление по воздуху), `main.cpp` (связывание).

### Почему всё в целых числах

Форматирование с одним знаком после запятой должно совпадать с проверенной
реализацией на Python, которая округляла десятичным `Decimal` по правилу
«половина вверх». На `double` значение 26.95 хранится как 26.9499999…, и
`printf("%.1f")` даёт 26.9 вместо 27.0. Поэтому температура хранится в
сотых долях градуса целым числом и округляется целочисленно. Это
проверяется тестом `test_live_sensor_value_rounds_up`.

### Почему сравнения времени сделаны вычитанием

`millis()` переполняется через 49.7 суток. Все сравнения вида
`now - last >= порог` на беззнаковых корректно переживают переход через
нуль. Прямое сравнение `now >= last + порог` привело бы к зависанию цикла
или ложной перезагрузке. Проверяется тестами
`test_millis_overflow_does_not_break_interval` и
`test_millis_overflow_does_not_cause_false_reboot`.

### Пороги восстановления

| Событие | Порог | Почему так |
|---|---|---|
| переинициализация стека BLE | 3 неудачных чтения подряд | тот же порог, что у серверного курьера для залипшего адаптера |
| перезагрузка платы | две трети срока годности показания | после перезапуска остаётся время доставить свежее значение до того, как принтер погасит нагрев |

## Питание

Понижающий модуль с 24 В на 5 В, вход на пин `5V` платы DevKit.
Обязательно электролит 470 мкФ по 5 В у самой платы: Wi-Fi даёт всплески
тока, без ёмкости возможна просадка и перезагрузка. Быстрый предохранитель
0.5 А по входу 24 В.

**Перед подключением замерить мультиметром**, что на выбранном разъёме
вентилятора напряжение постоянное, а не коммутируется вместе с сушкой.
Если коммутируется — брать с выходных клемм блока питания.

Запас есть: ACE в печати берёт около 12 Вт из 30 Вт блока питания,
нагреватели висят на сетевом напряжении отдельно, ESP32 берёт около 1.5 Вт.

## Опасность

**На плате ACE сетевое напряжение 220 В.** Работать только с вынутой
вилкой и выдержкой на разряд, все соединения в термоусадке. Плату ESP32
размещать в отдельном отсеке подальше от сетевой части, антенной к
пластиковой стенке.

Датчик рассчитан на работу до 60 °C, а сушка на этой машине настроена ровно
на 60 °C — запаса нет. Температура датчика передаётся вместе с влажностью
именно как контроль: устойчивый выход за предел означает, что температуру
сушки надо понизить.

## MQTT

Ветка `ace/rh` на брокере <server-ip>:

| Тема | Значение |
|---|---|
| `ace/rh/humidity` | влажность, целые проценты |
| `ace/rh/temperature` | температура датчика |
| `ace/rh/battery_mv` | напряжение батареи датчика |
| `ace/rh/delivered` | приняло ли последнее показание принтером |
| `ace/rh/silence_seconds` | сколько секунд нет доставленных показаний |
| `ace/rh/failures` | неудачных чтений подряд |
| `ace/rh/event` | события: запуск, сброс BLE, перезагрузка |

## Серверный курьер остаётся

`feeder/` не удаляется: это проверенный запасной путь на случай отказа
платы. Одновременно оба работать не должны — у них один и тот же датчик, и
второй потребитель BLE мешает первому подключиться.
